## Context

Local optimistic caches drifted from the store whenever a provider call failed
mid-stream. The interface would show a message that the backend had never
committed, and the only way back to agreement was a full refetch that discarded
whatever the reader was looking at.

The divergence was not a bug in one component. It followed from two components
each holding an opinion about what a session contained.

## Decision

The desktop application derives every piece of session state from the event
stream. It renders what it has been told, and it asks for a replay when it
suspects it has missed something.

- No local write path produces session state that an event did not carry.
- Optimistic interface affordances are visibly provisional until confirmed.
- A reconnect replays from the last processed identifier rather than refetching.

## Alternatives considered

A reconciling cache — apply optimistically, correct on the next event — was
rejected because the correction is visible to the reader as content changing
underneath them, and because the reconciliation logic is where the original
divergence lived.

## Consequences

First paint after a cold start waits for replay, which is the cost this
decision accepts. Attempts to remove that wait with a desktop-side copy have
been proposed and declined since.

The benefit is that "what does this session contain" has exactly one answer,
held by the backend, at every moment.
