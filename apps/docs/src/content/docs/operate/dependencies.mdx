## Desktop application

The desktop application is a Tauri app. Its checked-in build config expects:

- a frontend build produced from `apps/desktop`
- a Tauri host in `apps/desktop/src-tauri`
- Rust tooling for Tauri development and packaging

For local development, the repository root script runs `pnpm --filter
@lys/desktop run tauri dev`.

## Backend

In development builds, the desktop host launches `pnpm run dev` from the backend
directory in the checkout recorded at host compile time. This requires that
checkout, installed workspace dependencies, Node 24.10 or later, and `pnpm` on the process
search path. Release builds instead run `$LYS_HOME/runtime/node/bin/node` with
`$LYS_HOME/runtime/backend/backend.mjs`, both installed by `build.sh` on macOS;
see the [Lys home directory](/reference/configuration/#lys-home-directory).
Neither launch path uses a backend bundled inside the desktop app. `build.sh`
itself also needs `curl`, `jq`, and network access to `nodejs.org` to download
that runtime; see [Packaging and releases](/operate/releases/).

The backend itself depends on:

- an absolute `LYS_HOME` path and local filesystem access for
  `$LYS_HOME/lys_db.sqlite` in an existing directory; see
  [standalone startup](/develop/running/)
- SQLite support through Node's `node:sqlite`, Node 24.10 or later (the
  database owner uses `DatabaseSync.setAuthorizer`)
- an LM Studio instance reachable at `127.0.0.1:1234` for model features;
  startup does not require it

The backend's chat and model services are both wired to that LM Studio address.
The backend opens its HTTP listener at `127.0.0.1:12345` without waiting for LM
Studio, then makes one connection attempt. `GET /api/v1/heath` reports HTTP
readiness only. `GET /api/v1/llm/runtime` reports the LM Studio connection
status, and `POST /api/v1/llm/runtime/connect` retries it. A running
host-owned child is process status only.

## Docs site

The docs app builds with Astro and Starlight from `apps/docs`. The checked-in
GitHub Pages workflow uses:

- Node 24
- `pnpm --filter @lys/docs run build`
- `apps/docs/dist` as the deploy artifact

## What is not formalized yet

The repository does not currently publish:

- a supported OS-by-OS runtime dependency matrix
- installer prerequisites for desktop end users
- a documented production deployment target for the backend separate from the
  desktop host

This page reflects only the dependencies proven by checked-in scripts and
configuration.
