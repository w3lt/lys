The workspace structure is simple and explicit:

## Root workspace

- `package.json` owns the root developer commands such as `pnpm dev`,
  `pnpm docs:dev`, and `pnpm backend:dev`.
- `pnpm-workspace.yaml` includes `apps/*`, `packages/*`, and `scripts`.
- `VERSION` holds the release version that `scripts` writes into the package
  and desktop manifests.
- `build.sh` builds and installs the desktop app on macOS; see
  [Packaging and releases](/operate/releases/).

## Applications

### `apps/desktop`

The local desktop UI. It uses React, Vite, Zustand, and Tauri. It starts and
stops the backend through Tauri commands, opens the chat SSE stream, renders
conversation state for the user, and browses stored conversations.

### `apps/backend`

The local service process. It registers Fastify routes for health checks; model
inventory, health, load, and unload operations; conversation history; and the
chat stream. It also owns the SQLite conversation store and the LM Studio /
OpenAI-compatible service adapters.

### `apps/docs`

The internal engineering handbook. It is built with Astro and Starlight and
validates handbook frontmatter at build time.

## Shared packages

### `packages/protocol`

The transport contract shared between desktop and backend. It exports route
constants, request schemas, and stream event schemas.

### `packages/share`

The shared domain model package. Today it mainly defines the conversation and
message schemas reused by both transport and persistence code.

## Tooling

### `scripts`

The `@lys/scripts` workspace package. Its `version:sync` and `version:check`
scripts write or verify the root `VERSION` in every package manifest and the
two Tauri manifests; see [Package reference](/reference/packages/#lysscripts).
