## Docs deployment

The docs publication workflow runs independently of desktop releases:

- workflow: `.github/workflows/deploy-docs.yml`
- trigger: pushes to `main` and manual dispatch
- build command: `pnpm --filter @lys/docs run build`
- artifact directory: `apps/docs/dist`
- deploy target: GitHub Pages

## Desktop builds

The repository has no desktop build or release workflow under
`.github/workflows`, and the Tauri configuration sets up no code signing or
notarization. Desktop builds are made locally with `build.sh`.

## Local macOS install with `build.sh`

On macOS, `build.sh` at the repository root builds the desktop app from a
source checkout and installs it on the same machine. On any other operating
system it prints a message and exits without building. Run it from the
repository root:

```sh
./build.sh
```

The script stops at the first failing step. In order, it:

1. Runs `pnpm install --frozen-lockfile`.
2. Builds vmo, the page reader `read_page` uses, in release with
   `swift build -c release --package-path apps/vmo`. It stops first when the
   Swift toolchain is missing. Nothing is installed yet, so a machine that
   cannot build vmo keeps its current install.
3. Runs `pnpm run backend:build`, which bundles the backend into
   `apps/backend/dist/backend.mjs` and copies its prompt files beside it.
4. Creates `$LYS_HOME/runtime`, using `${LYS_HOME:-$HOME/.lys}`.
5. Downloads the newest Node.js release in the major version named by
   `.nvmrc`, or the latest LTS release when `.nvmrc` is absent, verifies it
   against that release's `SHASUMS256.txt`, and installs it at
   `$LYS_HOME/runtime/node`. A matching installed version is reused.
6. Moves `apps/backend/dist` to `$LYS_HOME/runtime/backend`, replacing the
   previously installed backend.
7. Replaces `$LYS_HOME/runtime/vmo` with a directory holding only the new
   `vmo` executable, and signs it ad hoc with the virtualization entitlement
   in `apps/vmo/vmo.entitlements`.
8. Runs `pnpm run desktop:build:ci` and `pnpm run desktop:bundle:ci`, which
   build the Tauri app without bundling and then bundle only `Lys.app`.
9. Removes any previously installed `/Applications/Lys.app`, then copies the
   new `Lys.app` there with `ditto`. Without the removal, files from the old
   bundle would remain inside the new one.

The script needs the toolchain from [Environment setup](/develop/setup/),
including the Swift toolchain, plus `curl`, `jq`, and network access to
`nodejs.org`, and to `github.com` for vmo's Swift packages until
`apps/vmo/.build` holds them. vmo builds and runs only on Apple silicon with
macOS 26; see [Runtime dependencies](/operate/dependencies/#vmo).

:::caution[Desktop runtime is still under development]
Release builds of the desktop app start the backend and vmo from a runtime
installed in the [Lys home directory](/reference/configuration/#lys-home-directory):
`$LYS_HOME/runtime/node/bin/node` running
`$LYS_HOME/runtime/backend/backend.mjs`, and `$LYS_HOME/runtime/vmo/vmo`. Only
`build.sh` installs that runtime, and only on the machine that runs it, so a
copied `Lys.app` cannot start its backend or vmo on a machine without it. The same reference explains why an app opened
from Finder or the Dock looks for the runtime under `~/.lys`.
:::

## Versioning

The root `VERSION` file holds the release version, currently `0.3.0`. The
`@lys/scripts` package writes it into the manifests or checks them:

```sh
pnpm --filter @lys/scripts run version:sync
pnpm --filter @lys/scripts run version:check
```

All checked-in workspace manifests, `apps/desktop/src-tauri/Cargo.toml`, and
`apps/desktop/src-tauri/tauri.conf.json` are currently versioned `0.3.0`.
`version:sync` does not rewrite `apps/desktop/src-tauri/Cargo.lock`; update its
`lys-desktop` entry in the same change. Each release is tagged `v<version>` in
Git, and the changelog's compare links rely on those tags. See the
[package reference](/reference/packages/#lysscripts) for what the scripts
rewrite, and the [changelog](/changelog/) for the recorded releases.
