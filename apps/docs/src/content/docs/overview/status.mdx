This page is intentionally conservative. It describes behavior visible in the
repository today; it is not a promise of unreleased work.

## Implemented now

- The desktop can start and stop the backend through the Tauri host.
- The backend exposes a health route, LLM inventory, load, and unload routes,
  chat, and conversation history routes.
- A chat turn creates or continues a conversation, inserts user and assistant
  rows in SQLite, and streams typed SSE events back to the desktop.
- Conversation history supports search, cursor pagination, transcript retrieval,
  rename, and deletion. Assistant deltas are persisted before publication;
  continuation uses the saved prompt and eligible stored history.
- Untitled conversations receive a generated title only if no rename has won
  the race. Interrupted streaming rows are recovered on backend startup.
- Runtime, Model, and Generation settings panes are available. Model controls
  refresh inventory, load and unload weights, and check loaded-state health.
- Generation controls apply to future chat requests and save automatically
  through Tauri to `~/.lys/settings.json`, which contains runtime, model, and
  generation groups. Runtime and model edits remain session-only.

## Coming soon

The current repository does not yet provide:

- desktop history-list and restore integration (the backend APIs are available)
- a Conversation settings pane
- using the selected default model for chat requests, which still send a fixed
  model identifier
- replay or reconnect semantics for chat streams
- tool-call stream events
- a production desktop release workflow
- evidenced ADR and RFC records, and a canonical release log
