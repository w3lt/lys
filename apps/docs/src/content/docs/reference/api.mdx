The current backend surface is small and lives entirely under the `@lys/protocol`
route definitions.

## Routes

| Method | Path               | Request body                                                  | Response              |
| ------ | ------------------ | ------------------------------------------------------------- | --------------------- |
| `GET`  | `/api/v1/heath`    | none                                                          | `{ ok: true }`        |
| `GET`  | `/api/v1/llm/list` | none                                                          | `{ llms: LlmInfo[] }` |
| `POST` | `/api/v1/llm/load` | `{ modelId: string }`                                         | `LlmInfo`             |
| `POST` | `/api/v1/chat`     | `{ message: string, model: string, conversationId?: uuidv7 }` | `text/event-stream`   |

`/api/v1/heath` is the current spelling in both the shared protocol package and
the Fastify route registration.

## Chat request body

```json
{
  "message": "Tell me what changed",
  "model": "google/gemma-4-12b-qat",
  "conversationId": "0198f5a5-7b9b-7e0b-9b0f-87d9d6a5f72d"
}
```

`conversationId` is optional. Omitting it asks the backend to create a new
conversation before sending the first stream event.

## Chat response shape

The chat route responds as SSE, not JSON. Each event payload must match one of
the six variants documented in [SSE events](/reference/sse-events/).

## LLM metadata shape

`LlmInfo` currently includes:

- `modelKey`
- `format`
- `displayName`
- `path`
- `sizeBytes`
- optional `paramsString`, `architecture`, and `quantization`
- `vision`
- `trainedForToolUse`
- `maxContextLength`
- `loaded`

## What is not part of the public API

- No conversation listing or history-retrieval endpoint; the chat route can
  continue only a conversation whose identifier the caller already knows
- No export or import endpoint
- No typed HTTP error taxonomy beyond route-local thrown errors
