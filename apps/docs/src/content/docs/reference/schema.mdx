The backend currently manages one SQLite schema and the Tauri host manages one
JSON schema for runtime, model, and generation settings.

## SQLite tables

### `conversations`

| Column       | Type            | Notes                                                                                                                                |
| ------------ | --------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `id`         | `TEXT`          | Primary key                                                                                                                          |
| `title`      | `TEXT`          | Null until the first title assignment; untitled turns request one, titled turns reconcile it to the client, and a rename replaces it |
| `agent_code` | `TEXT NOT NULL` | Code of the agent that answers the conversation; every turn sends that agent's current system prompt                                 |
| `created_at` | `TEXT NOT NULL` | ISO timestamp                                                                                                                        |
| `updated_at` | `TEXT NOT NULL` | ISO timestamp                                                                                                                        |

### `conversation_messages`

One row per message, and one row per part of a reply. A reply's row holds its
model and lifecycle; its reasoning, text, and tool calls are rows of their own
under it. The table is `STRICT`.

| Column            | Type            | Notes                                                                                                                                                 |
| ----------------- | --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`              | `TEXT`          | Primary key; a tool call's row uses the call's own UUIDv7                                                                                             |
| `conversation_id` | `TEXT NOT NULL` | Foreign key to `conversations(id)` with `ON DELETE CASCADE`                                                                                           |
| `role`            | `TEXT NOT NULL` | `user`, `assistant` (a reply), or one of a reply's parts: `reasoning`, `text`, `tool_call`                                                            |
| `reply_id`        | `TEXT`          | Parts only: foreign key to the reply's row with `ON DELETE CASCADE`                                                                                   |
| `position`        | `INTEGER`       | Parts only: zero-based order in the reply, unique per reply                                                                                           |
| `round`           | `INTEGER`       | Parts only: zero-based model round the part belongs to                                                                                                |
| `model`           | `TEXT`          | Required for reply rows, absent for every other row                                                                                                   |
| `content`         | `TEXT NOT NULL` | User text; a reasoning or text part's text, which grows with each stored fragment; a tool call's result once it has one; always `''` on a reply row   |
| `status`          | `TEXT`          | Reply: `streaming`, `completed`, `interrupted`, `failed`. Tool call: `awaiting-approval`, `running`, `succeeded`, `failed`, `rejected`, `interrupted` |
| `finish_reason`   | `TEXT`          | Reply-only: `stop` or `length`, null while not completed                                                                                              |
| `tool_name`       | `TEXT`          | Tool calls only: the called tool                                                                                                                      |
| `tool_arguments`  | `TEXT`          | Tool calls only: the model's argument text as it wrote it                                                                                             |
| `source_numbers`  | `TEXT`          | Succeeded tool calls only: JSON array of the numbers of the sources the result shows, in its order; null when it shows none                           |
| `created_at`      | `TEXT NOT NULL` | ISO timestamp                                                                                                                                         |
| `updated_at`      | `TEXT`          | Required for reply and part rows                                                                                                                      |

### `conversation_sources`

The numbered sources the tool calls of a conversation's replies showed. A
number keeps its source for the whole conversation. The table is `STRICT`.

| Column            | Type               | Notes                                                                              |
| ----------------- | ------------------ | ---------------------------------------------------------------------------------- |
| `conversation_id` | `TEXT NOT NULL`    | Foreign key to `conversations(id)` with `ON DELETE CASCADE`                        |
| `number`          | `INTEGER NOT NULL` | The source's number in the conversation, from 1; primary key with the conversation |
| `url`             | `TEXT NOT NULL`    | Non-empty address, unique in the conversation                                      |
| `title`           | `TEXT NOT NULL`    | Non-empty title as the tool showed it when the source was first numbered           |

### `conversation_attachments`

The files sent with a conversation's user messages. A number is given once
per conversation and never changes; a name is unique within its message
ignoring case. The table is `STRICT`.

| Column            | Type               | Notes                                                                                                             |
| ----------------- | ------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `conversation_id` | `TEXT NOT NULL`    | Foreign key to `conversations(id)` with `ON DELETE CASCADE`                                                       |
| `message_id`      | `TEXT NOT NULL`    | Foreign key to the user message's `conversation_messages(id)` with `ON DELETE CASCADE`; primary key with the name |
| `number`          | `INTEGER NOT NULL` | The attachment's number in the conversation, from 1; unique with the conversation                                 |
| `name`            | `TEXT NOT NULL`    | The file's name, `COLLATE NOCASE`: non-empty, neither `.` nor `..`, without `/`                                   |
| `kind`            | `TEXT NOT NULL`    | `image` or `text`                                                                                                 |
| `media_type`      | `TEXT`             | Images only: `image/png`, `image/jpeg`, or `image/webp`                                                           |
| `size_bytes`      | `INTEGER NOT NULL` | Size of the file, at least 0                                                                                      |
| `width`, `height` | `INTEGER`          | Images only: sides in pixels, at least 1                                                                          |

The file itself is at
`$LYS_HOME/attachments/<conversation_id>/<message_id>/<name>`; see
[Data and storage](/operate/data/).

### `tool_call_decisions`

One row per tool call stored since version 13: how the backend decided the
call before it ran, the answer that moved it on, and its outcome. The row is
written in the same transaction as the call's row and holds no argument
value; the call's row keeps the arguments. Nothing reads the table yet. The
table is `STRICT`.

| Column            | Type            | Notes                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `call_id`         | `TEXT`          | Primary key; foreign key to the call's `conversation_messages(id)` with `ON DELETE CASCADE`                                                                                                                                                                                                                                                                                      |
| `conversation_id` | `TEXT NOT NULL` | Foreign key to `conversations(id)` with `ON DELETE CASCADE`                                                                                                                                                                                                                                                                                                                      |
| `agent_code`      | `TEXT NOT NULL` | Non-empty code of the conversation's agent when the call was stored                                                                                                                                                                                                                                                                                                              |
| `tool_name`       | `TEXT NOT NULL` | The called tool, as the model named it                                                                                                                                                                                                                                                                                                                                           |
| `policy_effect`   | `TEXT`          | The tool call policy's answer when the call arrived: `allow`, `require-approval`, or `deny`; null when Lys's own checks failed the call first, because it names a tool the round did not offer or arguments the tool cannot take. A call the person allowed and the policy then denied, when it was decided again before running, keeps this answer; its result holds the denial |
| `policy_reason`   | `TEXT`          | `credential-file`, `outside-approved-folders`, `settings-unreadable`, or `blocked-address` for `deny`, `destructive-tool` for `require-approval`; null otherwise                                                                                                                                                                                                                 |
| `approval_mode`   | `TEXT`          | Mode the approval gate applied: `just-run` when the tool was saved as Just run, `ask-me` otherwise; null when the call never reached the gate                                                                                                                                                                                                                                    |
| `answer`          | `TEXT`          | Answer that moved a waiting call on: `allowed`, the rejection's reason, `declined` or `showFailed`, or `expired` when nobody answered in time; null while none came or none was asked for                                                                                                                                                                                        |
| `outcome`         | `TEXT NOT NULL` | The call's `status`, which a trigger copies on every change                                                                                                                                                                                                                                                                                                                      |
| `created_at`      | `TEXT NOT NULL` | The call's creation time                                                                                                                                                                                                                                                                                                                                                         |
| `updated_at`      | `TEXT NOT NULL` | The call's latest update time, copied with its status                                                                                                                                                                                                                                                                                                                            |

### `tool_search_call_decisions`

One row per tool call of a tool search's reply stored since version 16, such
as Armitage's `search_tools` and `recommend_tool` calls for a `find_tools`
call: how the backend decided the call and how it ended. That reply is never
stored, so the row is the call's only trace and keeps its argument text. The
row is written when the search's reply keeps the call, before it can run,
and only while the `find_tools` call is stored as running; a call that
cannot be recorded never runs. A search's call never reaches the approval
gate, so no mode or answer is kept. Nothing reads the table yet. The table
is `STRICT`.

| Column            | Type            | Notes                                                                                                                                                                                                  |
| ----------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `call_id`         | `TEXT`          | Primary key; the identity the search's reply gave the call                                                                                                                                             |
| `search_call_id`  | `TEXT NOT NULL` | Foreign key to the `find_tools` call's `conversation_messages(id)` with `ON DELETE CASCADE`                                                                                                            |
| `conversation_id` | `TEXT NOT NULL` | The `find_tools` call's conversation; foreign key to `conversations(id)` with `ON DELETE CASCADE`                                                                                                      |
| `agent_code`      | `TEXT NOT NULL` | Non-empty code of the agent that answered the search                                                                                                                                                   |
| `tool_name`       | `TEXT NOT NULL` | The called tool, as the model named it                                                                                                                                                                 |
| `argument_text`   | `TEXT NOT NULL` | The call's arguments, as the model wrote them                                                                                                                                                          |
| `policy_effect`   | `TEXT`          | The tool call policy's answer: `allow` or `deny`; null when Lys's own checks failed the call first. `require-approval` cannot be stored: a search asks nobody, so such a call fails the search instead |
| `policy_reason`   | `TEXT`          | `credential-file`, `outside-approved-folders`, `settings-unreadable`, or `blocked-address` for `deny`; null otherwise                                                                                  |
| `outcome`         | `TEXT NOT NULL` | `running` or `failed` when kept, then `succeeded` or `failed` when the run ends, or `interrupted` when the `find_tools` call stops running first                                                       |
| `created_at`      | `TEXT NOT NULL` | The call's creation time                                                                                                                                                                               |
| `updated_at`      | `TEXT NOT NULL` | The call's latest update time; when interrupted, the later of it and the `find_tools` call's update time                                                                                               |

### `agents`

| Column          | Type            | Notes                                                                          |
| --------------- | --------------- | ------------------------------------------------------------------------------ |
| `code`          | `TEXT NOT NULL` | Primary key; the agent's immutable identity, a lowercase slug                  |
| `name`          | `TEXT NOT NULL` | Non-empty display name                                                         |
| `bio`           | `TEXT NOT NULL` | Non-empty short description                                                    |
| `system_prompt` | `TEXT NOT NULL` | Non-empty system instruction                                                   |
| `created_at`    | `TEXT NOT NULL` | ISO timestamp, set when the agent is stored                                    |
| `updated_at`    | `TEXT NOT NULL` | ISO timestamp of the latest change; equals `created_at` until the first update |
| `deleted_at`    | `TEXT`          | ISO timestamp of the agent's deletion; `NULL` while it is not deleted          |

## Important constraints

- User rows must have non-empty content and no model, status, finish reason,
  or update time.
- Reply rows must have empty content, a non-empty model, a status, and an
  update time. Completed replies must also have a non-null finish reason;
  streaming, interrupted, and failed replies must keep a null one.
- User and reply rows have no `reply_id`, `position`, `round`, `tool_name`,
  `tool_arguments`, or `source_numbers`. Part rows must have a `reply_id`, a
  non-negative `position` and `round`, and an update time, and have no model
  or finish reason.
- Reasoning and text parts must have non-empty content and no status or tool
  columns.
- Tool calls must have a tool name, argument text, and status. Waiting,
  running, and interrupted calls have empty content; failed and rejected calls
  have non-empty content; only succeeded calls may have `source_numbers`,
  which must be valid JSON.
- The content checks of user rows, reasoning and text parts, and failed and
  rejected calls compare the content with `''`, so text that starts with a NUL
  character counts as non-empty. SQLite's `length()` stops at that character,
  so a check built on it would refuse such text.
- Sources must have a number of at least 1 and a non-empty URL and title; a
  conversation holds each number and each URL once.
- Attachment rows must have a number of at least 1, a name that is non-empty,
  neither `.` nor `..`, and without `/`, a size of at least 0, and either kind
  `image` with a non-empty media type and sides of at least 1 or kind `text`
  with a null media type and sides. SQLite checks only that; the shared
  attachment schema checks the rest, the media type's value and the name's
  byte length and NUL rule included, on every row the backend writes and
  reads.
- Conversation rows must have a non-empty `agent_code`; SQLite checks only
  that, and the shared conversation schema checks its agent code format on
  every row the backend writes and reads. A row added without the column gets
  `lys`, the default version 7 declared; the backend always writes the code,
  so that default is never used.
- Agent rows must have every column but `deleted_at`, and a non-empty `code`,
  `name`, `bio`, and `system_prompt`. SQLite checks only that, comparing each
  of the four with `''`, so text that starts with a NUL character still
  counts as non-empty, and that `deleted_at` is `NULL` or not `''`;
  `created_at` and `updated_at` have no check. The backend's agent schemas
  enforce the rest on every row it writes and reads: a code of at most 64
  lowercase letters, digits, and single inner hyphens; a name of at most 64
  and a bio of at most 128 UTF-16 code units; trimmed text without a lone
  UTF-16 surrogate; and millisecond ISO timestamps. A row that breaks them
  fails to read.
- Decision records must have a non-empty `agent_code` and an `outcome` that
  is a tool call status. A null `policy_effect` has no reason and no mode;
  `deny` has the reason `credential-file`, `outside-approved-folders`,
  `settings-unreadable`, or `blocked-address` and no mode;
  `require-approval` has the reason `destructive-tool` and a mode; `allow`
  has no reason and may have a mode. A mode is `ask-me` or `just-run`, and an
  answer, `allowed`, `declined`, `showFailed`, or `expired`, needs a mode. A
  comparison with `NULL` makes a check pass in SQLite, so every comparison on
  a nullable column is guarded with `IS NOT NULL`. SQLite does not check that a record's
  conversation, agent, and tool match its call's; the backend copies them
  from the call's row in the statement that stores the record.

The current backend inserts a reply row without parts before generation. It
then stores each part, and appends each fragment to the last reasoning or
text part, before publishing it, stores each change of a tool call before
publishing it, and finally updates the reply's status and finish reason. A
succeeded call's sources are stored in the same transaction as the call: a
URL the conversation already numbered keeps its row and title. Each tool
call's decision record is stored in the transaction that stores the call, and
the change that moves a waiting call on records its answer in the same
transaction. Ending a reply,
superseding it with a newer turn, and startup recovery mark its waiting and
running calls `interrupted`. Partial parts are retained on failure or
interruption.

### Reply parts

The shared `ReplyPart` type reads these rows: `kind` (`reasoning`, `text`, or
`tool-call`), `id`, `round`, `createdAt`, `updatedAt`, and `content` for
reasoning and text; `toolName`, `argumentText`, and `status` for a tool call,
with `result` for a succeeded, failed, or rejected call and `sourceNumbers`
for a succeeded one. A reply's
`parts` are its rows in `position` order, and a conversation's `sources` are
its source rows in `number` order.

## Indexes and triggers

| Name                                                 | Kind    | Purpose                                                                                                              |
| ---------------------------------------------------- | ------- | -------------------------------------------------------------------------------------------------------------------- |
| `conversation_messages_conversation_idx`             | index   | Orders messages by conversation, creation time, and id                                                               |
| `conversation_messages_reply_part_idx`               | index   | Unique: one part per position of a reply                                                                             |
| `update_conversation_after_message_insert`           | trigger | Updates `conversations.updated_at` after inserts, parts included                                                     |
| `update_conversation_updated_at`                     | trigger | Keeps explicit activity updates monotonic; title-only updates do not fire it                                         |
| `update_conversation_after_message_update`           | trigger | Updates `conversations.updated_at` after a row's `content` changes                                                   |
| `tool_call_decisions_conversation_idx`               | index   | Finds a conversation's decision records                                                                              |
| `update_tool_call_decision_after_tool_call_update`   | trigger | Copies a tool call's new `status` and `updated_at` into its decision record as its outcome                           |
| `tool_search_call_decisions_search_call_idx`         | index   | Finds the records of a `find_tools` call's search                                                                    |
| `tool_search_call_decisions_conversation_idx`        | index   | Finds a conversation's search call records                                                                           |
| `interrupt_tool_search_calls_after_tool_call_update` | trigger | Marks a search's calls still `running` as `interrupted` when its `find_tools` call's `status` changes from `running` |

`conversation_attachments` has no named index: SQLite builds the indexes of
its primary key on `(message_id, name)` and of its unique
`(conversation_id, number)` constraint. SQLite also builds the indexes of the
`tool_call_decisions` and `tool_search_call_decisions` primary keys.

## Migration strategy

The backend applies schema changes from an ordered array of steps, each an
SQL string or a function that runs inside the same transaction: for version
9, one that runs its statements and moves the stored reply text, and for
version 12, one that moves the records stored under `armitage`. It tracks
the applied version with `PRAGMA user_version`. Version 4 replaces only the
conversation timestamp trigger. Version 5 replaces only the message-update
trigger so that it fires on `content` changes; status-only updates no longer
count as conversation activity. Version 6 adds the `agents` table and changes
no existing row; builds that support only version 5 refuse to open a version-6
database. Version 7 adds `conversations.agent_code`, set to `lys` for every
existing conversation because Lys answered every earlier chat, and drops
`conversations.system_prompt`; the dropped prompts cannot be recovered, and
builds that support only version 6 refuse a version-7 database. Version 8
changes rows only: every conversation stored under `lys` moves to
`caliginia`, because Lys, the one agent shipped until then, is now shipped as
the built-in agents Caliginia and Lysiptera, and Caliginia is the one new
conversations start with. Titles, times, and messages stay, a conversation
under any other code keeps it, and an agent stored under `lys` stays the
user's own. Builds that support only version 7 refuse a version-8 database.
Version 9 rebuilds `conversation_messages` with reply parts, because SQLite
cannot change a table's checks in place, and adds `conversation_sources`. Every
message keeps its identity, times, and order. Each stored reply's text, which
holds every round's text joined by blank lines, becomes one `text` part of
round 0 with the reply's times; a reply without text gets no part. Version 9
cannot be undone, and builds that support only version 8 refuse a version-9
database. Version 10 adds `conversation_attachments` and changes no existing
row; builds that support only version 9 refuse a version-10 database.
Version 11 adds `agents.deleted_at`, `NULL` for every stored agent, because
deleting an agent now only marks it: the row stays, so its code is never
free again. Agents deleted before version 11 are gone, and their codes stay
free. Builds that support only version 10 refuse a version-11 database.
Version 12 changes rows only: a stored agent coded `armitage`, deleted or
not, and every conversation stored under `armitage` move to the first code
`armitage-<n>` (from `armitage-2`) that no agent or conversation holds,
because Armitage, the tool keeper, now ships under that code and a built-in
agent's code hides a stored agent's. Names, bios, prompts, times, a
deletion, titles, and messages stay, and a database without such rows is
left as it was. Builds that support only version 11 refuse a version-12
database. Version 13 adds `tool_call_decisions`, its index, and its trigger,
and changes no existing row: a call stored before it has no decision record,
because its decision was never stored. Builds that support only version 12
refuse a version-13 database. Version 14 creates `tool_call_decisions` again
so that `answer` may also be `expired`, copying every row unchanged, and
creates its index and trigger again; every other rule stays. Builds that
support only version 13 refuse a version-14 database. Version 15 does the
same so that `policy_reason` may also be `outside-approved-folders`, for a
call denied because it names a path outside the folders the person lets
tools use, or `settings-unreadable`, for one denied because it names a path
while those folders cannot be read from the settings file. Builds that
support only version 14 refuse a version-15 database. Version 16 adds
`tool_search_call_decisions`, its two indexes, and its trigger, and changes
no existing row: a search that ran before it has no record of its calls.
Builds that support only version 15 refuse a version-16 database.
Versions 1–3 are unchanged. Missing migrations
and the version marker commit together. At startup, streaming replies
become interrupted with a refreshed `updated_at`; their waiting and running
tool calls become interrupted too and keep their own `updated_at`. Parts,
conversation `updated_at`, and history order are preserved.

## Settings JSON

The Tauri host stores `runtime`, `generation`, `loadConfiguration`, `secrets`,
and `tools` groups in `$LYS_HOME/settings.json`. See the
[configuration reference](/reference/configuration/#persisted-settings-json)
for the current fields, defaults, and validation. Generation and load
configuration edits and the two runtime startup switches are saved
automatically; the other runtime edits in the desktop remain session-only.

The file carries no version marker, and loading converts nothing. A file
without a `loadConfiguration` group reads it as empty, and one without
`runtime.autoStartVmo` reads it as `true`; neither is rewritten. An older
file's `model` group is ignored and left out of the next save. The
missing marker is an approved exception until
[#146](https://github.com/w3lt/lys/issues/146); see the
[settings file version exception](/reference/standard-application/#settings-file-version-exception).
