## Shipped

<StatusBadge status="implemented" label="shipped" />

Session streaming is stable across all three processes. A message is persisted
before any provider call, reaches the interface only as an event, and survives a
reconnect through a bounded replay window. The desktop application holds no
independent copy of session truth, so there is one answer to what a session
contains at every moment.

## In flight

<StatusBadge status="accepted" label="in flight" />

Tool-call frames behind a capability flag. Partial `tool_call` frames let the
interface render a call as it is produced rather than after it completes; they
ship behind a protocol capability flag so host and interface can be released
independently. The proposal is accepted and not yet implemented, so current
architecture pages remain authoritative. See
[RFC-0012](/rfcs/rfc-0012-streaming-tool-call-frames/).

## Proposed

<StatusBadge status="discussion" label="proposed" />

Workspace-scoped sessions. Grouping sessions by the working directory they were
created in is under discussion; what a session should do when its directory is
moved or deleted is unresolved and currently blocks acceptance. See
[RFC-0013](/rfcs/rfc-0013-workspace-scoped-sessions/).

## Deliberately deferred

The following are deferred until a demonstrated need exists, rather than
planned: versioned documentation, end-user documentation, private
documentation or authentication, CMS authoring, comments, accounts and
analytics, translations, a generated API reference, and embedded AI assistance.

Deferred does not mean rejected. It means the work has no current sponsor and
no evidence of need, and a proposal is the way to change that.
