## Releases

- [Lys 0.3.0](/changelog/0.3.0/)

The log starts at 0.3.0. Earlier versions are recorded only by their Git tags.

## Where the release notes live

The root
[`CHANGELOG.md`](https://github.com/w3lt/lys/blob/main/CHANGELOG.md) is the
only authored copy of the release notes. It follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/): one
`## [<version>] - <YYYY-MM-DD>` section per release, newest first, with an
optional `## [Unreleased]` section above them.

When the handbook is built, each release section of that file becomes an entry
of the `changelog` content collection, and the release page for that version
renders the entry. The page and the file therefore show the same notes; do not
copy release notes into a page.

## Recording a release

1. Add the release's section to `CHANGELOG.md`, with a compare link for its
   heading at the end of the file.
2. In `apps/docs/src/content/docs/changelog/`, add `<version>.mdx` with
   `slug: changelog/<version>`, the next `sidebar.order`, and
   `<ChangelogRelease version="<version>" />` as its body.
3. Add the new page to the list of releases above.

The handbook build fails when a release page names a version that
`CHANGELOG.md` does not have, when two sections claim the same version, or when
a level-2 heading is neither a release heading nor `## [Unreleased]`. Every line
that begins with `## ` starts a section, including inside fenced code. Each
section is rendered on its own, so write links inline: a reference-style link
resolves only when its definition is in the same section. In `astro dev`, an
edited `CHANGELOG.md` appears after the dev server restarts.
