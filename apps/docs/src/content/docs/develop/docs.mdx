It is reviewed together with the behaviour it describes, so a change that makes
this page wrong is expected to update it in the same pull request. Where a
statement here depends on a durable decision, the decision is linked rather
than restated.

Content is validated at build time: invalid frontmatter, a duplicate
identifier, or a broken internal link fails the build rather than publishing a
partial page.
