## Backend health check

The backend registers a single health endpoint that returns `{ ok: true }` when
the Fastify app is running:

- route: `/api/v1/heath`
- method: `GET`

This is the only checked-in machine-readable diagnostics surface in the backend
today.

## Process logging

The backend enables Fastify's built-in logger, so request and application logs
are emitted on the backend process's standard output and standard error streams.

The checked-in code also includes explicit request-scoped debug and error calls
in the chat path, and the Tauri host writes at least one shutdown failure path
to stderr.

## Desktop runtime status

The desktop runtime settings pane exposes a small amount of process state:

- whether the backend is `running`, `starting`, `stopping`, or `stopped`
- the fixed backend address `127.0.0.1:12345`
- a derived uptime label while the backend is running

The same pane also exposes `Start` and `Stop` actions that call Tauri commands
to manage the backend child process.

## What is not implemented yet

The repository does not currently prove support for:

- log files or log rotation
- diagnostics bundles
- redaction policies for exported diagnostics artifacts
- a documented incident-sharing workflow

:::note[Coming soon]
File retention, log rotation, diagnostics bundles, and export/redaction rules
should be added to this page only after the repository ships them as supported
behavior.
:::
