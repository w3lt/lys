## Summary

Keep a desktop-side copy of the most recent session so the interface can paint
before the backend has finished starting.

## Motivation

A cold start shows an empty session list for as long as the backend takes to
open its store. On a slow disk that was measured at just over a second, which
reads as a broken launch rather than a slow one.

## Why it was rejected

The cache would have made the desktop a second holder of session truth, which
[ADR-0004](/decisions/adr-0004-desktop-state-from-events/) closed
deliberately. The
proposal had no answer for a cache that disagreed with the store after an
interrupted write, and the discussion did not find one that stopped short of a
full reconciliation contract.

The underlying complaint was addressed instead by rendering a determinate
loading state for the session list, which removed the appearance of failure
without introducing a second writer.
