## Context

Lys ran as a single process. Provider credentials had exactly one consumer — the
code that constructed provider requests — and every additional hop between the
keychain and that code was a place for a secret to be copied or logged.

## Decision

The provider layer resolves credentials from the operating-system keychain at
the point of use, immediately before constructing a request, and holds no
long-lived copy.

## Alternatives considered

Loading credentials once at startup into a process-wide store was rejected
because it extended a secret's lifetime from one call to one session for no
measured benefit.

## Consequences

Credential handling stayed in one place and was easy to review. The decision
assumed a single trust domain, which stopped being true once the backend was
split into its own process; ADR-0007 records the replacement.
