The current security posture is intentionally simple and local. The backend and
LM Studio both run on loopback, request and event payloads are validated with
Zod, and there is no credential-management subsystem yet. There are two
outbound connections, and both start off: the `read_page` tool asks vmo, a
page reader on the same machine, to read a public web page in a headless
browser inside a micro VM, which also loads what the page needs, and the
`web_search` tool sends a query and the person's Tavily
API key to Tavily's search service. Each runs after the person allows the call, or
at once when the person set that tool to Just run, a choice Lys saves. The
backend decides which calls ask; the desktop shows the prompts. The clock and
location tools, `get_current_time` and `get_location`, reach no network: their
results go to the backend and on to LM Studio, both on loopback.

The MCP servers the person adds in Settings → MCP go further. The backend
starts each stdio server's command as the person's OS account, or connects to
each remote server's URL with the configured headers, and a call of one of
their tools runs on that server, which decides what the call reaches. Their
tools start switched on, because adding a server is the person's choice, and
each call still asks first unless the person set the tool to Just run; see
[MCP servers](#mcp-servers).

## Current trust boundaries

| Boundary                     | Current state                                                                                                                                                                                                                          |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| React UI -> Tauri host       | Trusted application boundary using Tauri `invoke` commands.                                                                                                                                                                            |
| React UI -> Fastify backend  | Loopback HTTP and SSE only. No auth layer beyond local binding.                                                                                                                                                                        |
| Fastify backend -> LM Studio | Loopback connections to local LM Studio HTTP and WebSocket endpoints.                                                                                                                                                                  |
| Backend -> SQLite file       | Local filesystem access to `$LYS_HOME/lys_db.sqlite`.                                                                                                                                                                                  |
| Backend -> attachment files  | Local filesystem access to `$LYS_HOME/attachments/`: the files of each chat request are written under the conversation's and the message's identifiers and the file's own name, read for the model, and removed with the conversation. |
| Tauri host -> settings file  | Local filesystem access to `$LYS_HOME/settings.json`; `get_location` reads its `location` group and never creates or writes the file.                                                                                                  |
| Tauri host -> system clock   | `get_current_time` reads the system clock and the machine's time zone, from `TZ` or else `/etc/localtime`.                                                                                                                             |
| Tauri host -> user files     | File tools read any path the OS user running Lys can read.                                                                                                                                                                             |
| Tauri host -> vmo            | The host starts vmo as the OS user running Lys, ad hoc signed with the virtualization entitlement, stops it with `SIGTERM` and, after 60 seconds, `SIGKILL`, and asks its `GET /health` over loopback TCP.                             |
| Backend -> vmo               | Each tool lookup sends `GET /health` to vmo, and each `read_page` call sends the page's URL, over loopback HTTP on `127.0.0.1:8080`, without authentication.                                                                           |
| vmo -> micro VM -> web       | vmo reads the page in headless Chromium in a fresh micro VM, which loads the page, its redirects, and what it loads.                                                                                                                   |

| Backend -> settings file     | Reads the Tavily API key, the saved Just run choices, and the MCP servers from `$LYS_HOME/settings.json`; the Tauri host is the only writer.                                                                                           |
| Backend -> stdio MCP server  | The backend starts each configured command as the OS user running Lys, without a shell, in the person's home folder, and speaks MCP over its standard input and output; the process can do whatever that account can.                  |
| Backend -> remote MCP server | Streamable HTTP to the configured URL, `https`, or `http` only for `localhost`, `127.0.0.1`, or `[::1]`, with the configured headers; redirects are not followed.                                                                      |

## Current controls

| Control                     | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Loopback host constants     | Backend and LM Studio addresses default to `127.0.0.1`.                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| CORS policy                 | Fastify admits only the `http://localhost:1420` and `http://127.0.0.1:1420` development origins and the `tauri://localhost` app origin.                                                                                                                                                                                                                                                                                                                                                   |
| Zod validation              | Backend validates route bodies, parameters, and query strings; desktop validates SSE payloads and HTTP responses.                                                                                                                                                                                                                                                                                                                                                                         |
| Attachment name rule        | An attachment name is non-empty, neither `.` nor `..`, holds no `/` and no control character (NUL included), and has at most 255 UTF-8 bytes, so it names one entry of its message's folder; the shared schema refuses any other name with `400`. The file store builds every path only from a validated UUIDv7 and such a name, under the attachments directory, and creates each message folder and each file exclusively.                                                              |
| Attachment content check    | What a file is comes from its bytes, never from its name: a PNG, JPEG, or WebP header, or UTF-8 text without a NUL character. Anything else is refused with `400`, and an image is refused with `409` for a model without vision.                                                                                                                                                                                                                                                         |
| Attachment reader scope     | `read_attachment` reads only the text files the conversation's stored rows name, by attachment number, never a path the model supplies. It runs without asking, since the person attached the files.                                                                                                                                                                                                                                                                                      |
| Agent state scope           | The agent state tools only read: who an agent is, its role, and what its live instance is working on. Roles are fixed in code from the agent's kind: a built-in agent may find every agent and read any agent's state; a stored agent may read only its own. The backend checks the asking agent's role before it reads anything.                                                                                                                                                         |
| Route-local abort handling  | Closing the SSE connection aborts the backend chat task.                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Approval gateway            | The backend's tool approval service decides every tool call, client, backend, and MCP tools alike, except `read_attachment`, which runs without approval because it reads only what the person attached, and the agent state tools, which only read what agents are doing: a tool asks first unless it is saved as Just run in `settings.json`, and every call asks when that file cannot be read. The desktop shows the prompts and runs only the client tools' calls the backend sends. |
| Approval of web reads       | `read_page` runs only once the person allows the call on the card (full URL), or at once on Just run. Allowing a read lets the page load what it needs from public hosts. It starts off.                                                                                                                                                                                                                                                                                                  |
| Address rule                | A read whose URL names, or whose host name resolves to, a loopback, private, link-local, shared, documentation, benchmarking, multicast, or reserved address is refused before vmo is asked. Only that URL is checked; see [Web reads](#web-reads).                                                                                                                                                                                                                                       |
| VM isolation                | Each read runs in a fresh micro VM that vmo deletes before it answers; nothing is kept between reads.                                                                                                                                                                                                                                                                                                                                                                                     |
| Invisible character removal | Every network or MCP tool's result loses Unicode format and control characters, such as zero-width, direction, and tag characters, and every variation selector but one emoji- or text-style selector after a visible character, and says how many it lost.                                                                                                                                                                                                                               |
| Untrusted page framing      | Page text and the page's title, site, and date reach the model between delimiters it cannot forge, with a notice never to obey them.                                                                                                                                                                                                                                                                                                                                                      |
| Approval of searches        | `web_search` runs only once the person allows the call on the card (full query and "Sends the query to Tavily (api.tavily.com)"), or at once on Just run. It starts off.                                                                                                                                                                                                                                                                                                                  |
| Fixed search destination    | Every search goes to `https://api.tavily.com` with certificate verification forced on, TLS 1.2 or later, no redirects, and the address rule on every resolved address and the connected socket.                                                                                                                                                                                                                                                                                           |
| Search key handling         | The key goes only into the `authorization` header sent to Tavily; it never appears in results, the model's context, events, API answers, logs, or errors.                                                                                                                                                                                                                                                                                                                                 |
| Typed location only         | `get_location` returns only the city, region, and country the person saved in Settings → Tools, and fails with `locationNotSet` when none is saved. Lys never asks Location Services, an IP lookup, or the time zone where the person is. Like every client tool, a call asks first unless the tool is on Just run.                                                                                                                                                                       |
| Owner-only settings file    | `settings.json` is replaced atomically and is readable only by its owner on Unix.                                                                                                                                                                                                                                                                                                                                                                                                         |
| Owner-only backend log      | Each of the backend's log files in `logs/` is created readable and writable only by its owner.                                                                                                                                                                                                                                                                                                                                                                                            |
| Untrusted result framing    | Result titles, URLs, and snippets reach the model between delimiters it cannot forge, with a notice never to obey them.                                                                                                                                                                                                                                                                                                                                                                   |
| MCP server rules            | A server's name, command, arguments, variables, URL, and headers follow the shared rules, which the host checks before it writes the file and the backend checks before it applies the group: no control characters, a URL with no user name, password, or `#`, and no header the transport sets itself. A group that breaks them is not applied.                                                                                                                                         |
| Connected MCP tools only    | A server's tools are listed and can be offered only while it is connected, and a call runs on the server as it is connected when the call runs; a chat request that offers a tool whose server is not connected is refused.                                                                                                                                                                                                                                                               |
| Untrusted MCP framing       | An MCP tool's result reaches the model between delimiters it cannot forge, after a notice never to follow it, cut at 20,000 characters; images, audio, and binary resources are named, not passed on.                                                                                                                                                                                                                                                                                     |
| MCP settings stay out       | The server list the backend answers names each server, its transport, and its state, never a command, argument, variable, URL, or header. The host's `Debug` output shows a command's argument count and a URL without its query, never an argument, a variable's or a header's value; a validation error about a server never quotes a value.                                                                                                                                            |

## Candid limits

- There is no keychain integration. The Tavily API key and the saved
  location are stored as plain text in `settings.json`, readable by the
  person's OS account and by any process running as it.
- There is no scoped credential-handle layer.
- The saved Just run choices live in `settings.json`, so any process running
  as the person's OS account can edit the file to put a tool on Just run. The
  backend reads them for every round of tool calls.
- The backend reads the Just run choices, like the Tavily API key, from the
  `settings.json` on its own machine. A backend running on another machine
  would need another source for them.
- Switching a tool or tool calls off does not stop a reply already running;
  it applies from the next message. Stop ends a running reply at once.
- There is no auth token or CSRF layer on the loopback backend, and it checks
  neither the `Host` nor the `Origin` header, so a page that uses DNS
  rebinding can call it like a local process
  ([#171](https://github.com/w3lt/lys/issues/171)).
- Nothing ties an answer to an approval prompt to the person. Any caller that
  reaches the backend, a local process or a page that uses DNS rebinding, can
  read a waiting prompt from the reply's events and answer it with `allowed`.
  For the client tools, such as `read_text_file`, `search_files`, and
  `get_location`, the desktop then runs the call with
  the person's account on a reply it follows, including one it starts
  following when the person opens the conversation, and even while the call's
  card still waits for the person. The model reads what the call returns.
  This stays open until callers are authenticated
  ([#171](https://github.com/w3lt/lys/issues/171)).
- Every tool call's full result is stored with its reply: the text of a file
  `read_text_file` read, the matches of `search_files`, the time
  `get_current_time` read, the location `get_location` returned, and the
  evidence of `web_search` and `read_page`. Any caller that reaches the backend can read
  it through the conversation and reply-event routes until the conversation is
  deleted, so a call answered as above exposes the file's text to that caller
  ([#171](https://github.com/w3lt/lys/issues/171)).
- A saved location reaches a model whenever a call of `get_location` runs:
  on Ask me once the person allows it, and on Just run without the person
  seeing the call. The location is then part of that reply's stored result
  until the conversation is deleted, also after the person changes or removes
  it in Settings.
- A stdio MCP server runs as the person's OS account with the command the
  person configured: it can read, change, and send anything that account can,
  and Lys does not confine it. A command such as `npx -y <package>` runs
  whatever the package registry serves at each start. Closing a server
  signals only the process Lys started, not the processes it started in turn.
- An MCP server writes its tools' descriptions, input schemas, and results,
  and all reach the model. A description is offered as the tool's
  description, cleaned of invisible characters and cut to 4,096 characters,
  and an input schema as the server wrote it, both without framing, so a
  server can put instructions in either; a tool whose name or schema holds a
  character a person cannot see is not listed, so Settings shows the text
  the model reads. Results are framed as untrusted, which
  lowers the risk but cannot remove it. On Just run, an MCP tool's calls run
  with no card shown.
- The environment variables and headers of the MCP servers are stored as
  plain text in `settings.json`, like the Tavily API key, readable by the
  person's OS account and by any process running as it. A stdio server
  receives its variables, and a remote server its headers, with every
  request. A key in a URL's query is stored the same way; Settings → MCP
  shows the URL with its query hidden as `?…` in the list and the details,
  but the editor's URL field shows it whole.
- A stdio MCP server's standard error lines reach the backend log as the
  server wrote them, each cut to 2,000 characters. An error is logged with its
  message and stack, each cut to 2,000 characters, which can carry part of
  what the server answered; an HTTP error answer is logged only by its status.
  Whatever a server prints there, such as a token it echoes, stays in the log
  files.
- Any caller that reaches the backend, a local process or a page that uses DNS
  rebinding, can list the MCP servers' names and states, make the backend
  start the configured commands again or reach the configured URLs through
  sync and reconnect, and answer an MCP call's approval prompt with
  `allowed` ([#171](https://github.com/w3lt/lys/issues/171)).
- Attachment files are stored as sent, unencrypted, under
  `$LYS_HOME/attachments`, readable by the person's OS account and any process
  running as it. The folders and files are created with the process's default
  mode, so the umask decides who else can read them; keep `$LYS_HOME`
  readable by the account alone. Any caller that reaches the backend can send a chat request
  with attachments, so it can write up to 20 MiB of files per message there,
  and a `read_attachment` result is stored with its reply like every other
  tool result ([#171](https://github.com/w3lt/lys/issues/171)).
- An agent's state reads name the title of every conversation the read
  agent is working on: `read_my_state`, offered to every agent, names the
  titles of the asking agent's own conversations, and a built-in agent's
  reads of other agents name theirs. So a reply in one conversation can show
  the title of another, and its stored result keeps that title after the
  other conversation is renamed or deleted. Any caller that reaches the
  backend can chat with any agent and so learn the titles of that agent's
  conversations, and with a built-in agent those of every agent
  ([#171](https://github.com/w3lt/lys/issues/171)).
- Each live agent works on at most two replies at once and lets at most
  eight more wait, so any caller that reaches the backend can fill an
  agent's request slots and line with its own chats; until those end, the
  person's new messages to that agent wait or fail with an `error` event
  ([#171](https://github.com/w3lt/lys/issues/171)). The limits bound the
  model requests and waiting replies of each agent, not of all agents.
- Deleting a stored agent keeps its row, its system prompt included, in
  `lys_db.sqlite`, so that its code is never reused; Lys offers no way to
  erase it.
- `read_page` runs the scripts of pages the model chooses in Chromium inside
  vmo's micro VM, with Chromium's own sandbox off, so the VM alone confines
  them. The browser is the Alpine `chromium-headless-shell` package of the
  `lys-readpage` image, whose `latest` tag vmo fetches at each start. It gets
  security fixes only when the image is rebuilt on `main`, by a change under
  `sandboxes/readpage` or a manual run of its workflow, and vmo uses the new
  build from its next start. Whoever can publish that tag decides which reader
  the next vmo start runs.
- The address rule covers only the URL Lys is asked to read. vmo applies no
  rule of its own, so a redirect, a request the page's scripts make, or a
  name that resolves differently inside the VM can reach any address the
  VM's network reaches, a private network the machine is on included, and
  the HTML of what it reached then goes to the model.
- vmo does not authenticate its callers: any process on the machine can ask
  it to read a page. Stop and the backend's time limit do not stop the VM of
  a read, which runs until vmo's own 30 seconds end it, and nothing limits
  how many reads run at once.
- Nor do the backend and the host authenticate vmo: whatever listens on
  `127.0.0.1:8080` and answers `GET /health` with `200` makes `read_page`
  available and receives the URL of every read. While vmo is stopped, any
  local process can take that port.
- A vmo killed after the 60-second stop timeout, or ended with `kill -9`, may
  leave VMs running. A vmo or backend whose Lys died without quitting keeps
  running ([#202](https://github.com/w3lt/lys/issues/202)).
- Hidden text reaches the model. `read_page` reads everything a page holds,
  text it hides from view included, such as a closed accordion, text moved
  off-screen, or white text on white, because the content is what a read is
  for. Instructions a page hides from the person therefore reach the model as
  page content, inside the untrusted framing. That includes the text a web
  component keeps in an open shadow root, even for its controls, such as a
  copy button's label. The content of a closed shadow root or an iframe is
  not read.
- Removing invisible characters removes a few visible signs too, such as the
  Arabic number signs (U+0600–U+0605) and the end-of-ayah sign (U+06DD),
  turns the England, Scotland, and Wales flags into a plain black flag, and
  shows a character a variation selector picked an alternate shape for in
  its default shape.
- A page's third parties, such as analytics and CDNs, see a request from the
  machine Lys runs on, as they would from any browser.
- The current Tauri configuration sets no Content Security Policy (`csp` is
  `null`).
- The backend currently uses a dummy API key value when talking to local
  OpenAI-compatible LM Studio endpoints that expect an API key field.
- Runtime settings and conversation data live on disk in user-space files.
- The backend's log files keep every request's full URL, history searches
  included, and the failures the backend reports on disk without redaction,
  and Lys never deletes them, under the
  [request log exception](/reference/standard-application/#request-log-exception).

## Web reads

`read_page` reads any public URL the model chooses: there is no allow list,
because the person approves the calls, each one on Ask me or all of them on
Just run, which Lys saves until the person switches the tool back. Allowing a
read lets the page load what it needs, as any browser visit does; the card
names the page. The protections are about which pages a read may ask for and
what reaches the model:

- **Arguments.** A URL that is not absolute `http` or `https`, is longer than
  2,048 characters as given or once normalized and percent-encoded, carries a
  username or password, or names `localhost` or a blocked IP address is
  answered without asking. The WHATWG URL parser normalizes odd spellings of
  an address, such as `http://2130706433/`, first, and vmo passes the
  normalized URL to the reader unchanged.
- **Connections.** Before it asks vmo, the backend looks up the URL's host
  name through the operating system and refuses the read when any address is
  blocked; IPv4-mapped IPv6 addresses are matched against the IPv4 rules.
  Nothing else a read connects to is checked: vmo applies no address rule, so
  a redirect, a request the page's scripts make, or a name that resolves
  differently inside the VM can reach any address the VM's network reaches.
- **Redirects.** HTTP, `<meta>` refresh, and script redirects are followed
  to any host, unchecked. vmo does not say where they led, so the result
  cites the URL Lys was asked to read, and the page there is read whatever
  its HTTP status or media type.
- **Isolation.** Each read runs in a fresh micro VM that vmo creates from the
  `lys-readpage` image it fetched at its start and deletes before it answers,
  so cookies or storage a page sets last for that read only. Chromium runs as
  a user without root inside the VM, with its own sandbox off. Lys never signs
  in, so it reads what a signed-out visitor sees. Requests carry the browser's
  own `User-Agent`.
- **Bounds.** vmo gives one read 30 seconds, and the backend gives the whole
  read, the host lookup and vmo's answer included, 60 seconds. The backend
  reads at most 16 MiB of vmo's answer and cuts the page's HTML at 4 Mi
  UTF-16 code units; markup with more than 40,000 start tags, or a parsed
  page with more than 40,000 elements or a nesting depth sum above 400,000,
  is refused before Readability runs. Nothing limits the connections a page
  makes, the bytes it receives, or the memory its scripts hold beyond what
  the VM has.
- **Hidden and invisible text.** Lys reads hidden text like any other text:
  the reader in the VM drops styles, `<link>` elements, and `style`
  attributes, so no stylesheet applies, and the backend drops the `hidden` and
  `aria-hidden` attributes before it extracts the main text. The result, like
  every network tool's result, then loses format and control
  characters other than tabs and line breaks, and every variation selector
  except one emoji- or text-style selector after a visible character, and
  says how many it removed; a zero-width joiner or non-joiner stays only
  between two visible characters.
- **Prompt injection.** The model is told that page content is untrusted and
  must never be followed. This lowers the risk but cannot remove it: a page
  can still try to steer the reply with any of its text, hidden or visible. On Ask me, each further tool call still needs
  the person's approval. On Just run it does not: with `read_page` and a file
  tool both on Just run, a page's instructions can lead the model to read a
  file and send its content in the URL of a second `read_page` call, with no
  card shown. The pane says so for every `network` tool on Just run, and Ask
  me stays the default for every tool.

vmo runs on the backend's machine and reads from that machine's network
position. Today the backend runs on the same machine as the desktop.

## Web searches

`web_search` sends the query the model wrote to the Tavily Search API with
the person's API key. It is unavailable, and never offered to a model, until a
key is saved in Settings → Secrets.

- **What is sent.** The query (at most 400 characters, none of which is
  hidden on screen), the key in the `authorization` header, and Lys's
  `User-Agent`. Nothing else from the
  conversation leaves the machine unless the model puts it into the query. No
  cookie, `Referer`, or proxy is used.
- **Where it goes.** Always `https://api.tavily.com`, a constant the model
  cannot change. Certificate verification is forced on whatever the
  environment says, and TLS 1.2 is the minimum. The address rule of
  `read_page` also applies: if `api.tavily.com` resolved to this machine or a
  private network, Lys would not connect, so the key never goes there. A proxy
  or VPN that answers every name with an address of its own, as Clash and
  Surge do in their fake-IP mode (198.18.0.0/15), therefore makes every search
  and Test fail. A redirect is not followed.
- **What comes back.** At most 5 results with a title (300 characters), URL,
  and snippet (500 characters), from a body of at most 1 MiB within 15
  seconds. Results whose URL `read_page` could not read are left out. Titles,
  URLs, and snippets sit between delimiters the results cannot write, with a
  notice never to follow them.
- **The key.** Saved by the Tauri host in `settings.json`, which is replaced
  atomically and is owner-only on Unix. The backend reads it when it lists the
  tools, when a chat request offers `web_search`, and when the person presses
  Test, and never logs it or anything else read from the file; a parse error,
  which could quote the key, is dropped. A turn keeps the key it started with.
  Test asks Tavily's usage endpoint, which reports whether the key works and
  its plan credits, and spends two credits each time.
- **Tavily sees every query**, tied to the person's account. Tavily's account
  setting "Allow Use of Query Data" controls whether Tavily uses queries to
  improve its service; switching it off is recommended.
- **Prompt injection.** A page read with `read_page`, or a snippet, can try to
  make Lys put private text, such as a file she read, into a query. On Ask me
  the card shows the full query before anything is sent; on Just run nothing is
  shown. A query is at most
  400 characters, and one holding a character a person cannot reliably see,
  such as a zero-width, direction, tag, or variation selector character, or a
  Hangul filler, is refused before anyone is asked, so the card never shows
  less than is sent. The zero-width joiner of an emoji sequence and the
  variation selector of an emoji such as `❤️` count too. Spaces other than
  the plain space, such as U+2003 or the ideographic space U+3000, and the
  blank braille pattern U+2800 are sent: the card shows each as a gap, but
  not which one it is, so a run of them could carry a few bits. They are
  allowed because Chinese and Japanese text and pasted text use them, and a
  hidden message would need a long run of visible gaps.
- **Local callers.** The loopback backend has no authentication, so any local
  process, including one run by another user account on the machine, can ask
  it to check the key, or send a chat request that offers `web_search` and
  answer its approval prompts with `allowed`, or need no answer while
  `web_search` is on Just run, which runs searches with the saved key.
  Both spend the person's Tavily credits. No answer contains the key: the key
  check says only whether it works, and searches return only results. Such an
  `allowed` answer can also make the desktop run a file tool's call; see
  [Candid limits](#candid-limits).
- **Web pages.** A page open in the person's browser cannot do either from its
  own site: the key check and a chat request are `POST`s with a JSON body,
  which need a CORS preflight that the backend refuses for every origin but
  the desktop's. A page that uses DNS rebinding reaches the backend under its
  own name, needs no preflight, and can do what a local process can
  ([#171](https://github.com/w3lt/lys/issues/171)).

## MCP servers

The person adds MCP servers in Settings → MCP; the host saves them in the
`mcp` group of `settings.json`, and the backend applies the group when it
starts and when the desktop asks it to sync. A server is either a command the
backend starts (stdio) or a URL it sends requests to (Streamable HTTP). See
the [configuration reference](/reference/configuration/#mcp-servers) for the
rules and the [API reference](/reference/api/#mcp-servers) for the routes.

- **What a stdio server gets.** The command runs without a shell, in the
  person's home folder, as the person's OS account. Its environment is `HOME`,
  `LOGNAME`, `PATH`, `SHELL`, `TERM`, and `USER` from the backend's, plus the
  configured variables, which win; nothing else of the backend's environment
  is passed on. It receives each call's arguments and can do anything the
  account can.
- **What a remote server gets.** Each request goes to the configured URL with
  the configured headers. Plain `http` is accepted only for `localhost`,
  `127.0.0.1`, and `[::1]`; no address rule applies otherwise, so a URL on a
  private network is reached as written. A redirect is not followed. Lys does
  not sign in with OAuth ([#253](https://github.com/w3lt/lys/issues/253)).
- **What reaches the model.** Each listed tool's name, description, and input
  schema, at most 128 tools per server, and the result of each call that ran.
  A result sits between `<<<mcp result>>>` delimiters the server cannot write,
  after a notice never to follow it, and loses invisible characters like a
  network tool's result. A tool whose schema Lys cannot check, or larger than
  64 KiB, is not listed, and neither is one whose name or schema holds a
  character a person cannot see, since Lys sends both unchanged.
- **Approval.** Every call of an MCP tool asks the person first unless the
  tool is on Just run; MCP tools start switched on, because adding the server
  is the person's opt-in, and none starts on Just run. Before asking, the backend
  checks only the arguments' shape: a JSON object of at most 256 KiB whose
  keys follow the argument name rule. The server checks the values.
- **Choices kept by name.** A tool's switch and Just run choice are saved
  under the name the model calls it by, `mcp__<server>__<tool>`, and stay
  when the server is removed or renamed. A server saved later under an
  earlier server's name therefore keeps that server's Just run choices for
  tools of the same name, without asking again. Renaming a server resets
  its tools to their defaults, switched on and Ask me, so a tool switched
  off comes back on; the choices under the old name apply again to a server
  saved under it.
- **Prompt injection.** A server, or a page or file one of its tools reads,
  can try to steer the model, and a description is not framed as untrusted.
  On Ask me each further call still needs the person's approval; on Just run
  it does not, so an MCP tool and a file tool both on Just run can move a
  file's text to the server with no card shown.
- **Time and size.** Connecting and reading the tool list take at most two
  minutes, and a call at most five; Stop tells the server a call was
  cancelled. The backend reads at most 16 MiB of one answer: an HTTP body,
  one event of an event stream the SDK reads one event at a time, or a stdio
  message line; a longer answer ends the connection and fails every request
  in flight at once. A result is cut at 20,000 characters.
- **Output schemas.** A tool's output schema is never compiled or checked, so
  a server cannot make the backend run a regular expression it chose; a
  result's structured content is read as untrusted JSON within Lys's limits.
- **Local callers and web pages.** Sync and reconnect are `POST`s with a JSON
  body, which a page on another site cannot send without a CORS preflight
  that the backend refuses. A local process, or a page that uses DNS
  rebinding, can call them; see [Candid limits](#candid-limits).

## Practical implication

Loopback binding limits network exposure, but this development architecture
must not be described as a hardened secret-management boundary. The codebase
does not yet implement those guarantees.
