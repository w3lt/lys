## Core runtime terms

- **Desktop**: the React user interface in `apps/desktop`.
- **Tauri host**: the native shell around the desktop app. It owns native
  commands such as backend start and stop.
- **Backend**: the Fastify process in `apps/backend` that serves HTTP routes,
  streams chat events, and persists conversations.
- **Protocol**: the shared HTTP and SSE contract exported by
  `packages/protocol`.
- **Share**: the shared domain-model package exported by `packages/share`.
- **Service**: a backend class named for its module, such as `AgentService`,
  `ChatService`, or `LlmService`, that the composition root creates once per
  backend and installs on Fastify (`app.agentService`, `app.chatService`) to
  own that module's operations.

## Conversation terms

- **Conversation**: the stored chat unit with metadata such as ID, title, the
  code of the agent that answers it, and timestamps. A new conversation names
  its agent; a continued one keeps it.
- **Built-in agent**: an agent that ships with the backend: Caliginia
  (`caliginia`), Lys's dark side, and Lysiptera (`lysiptera`), her light side.
  A built-in agent is never stored, changed, or deleted, and no stored agent
  can take its code. A new conversation starts with Caliginia unless another
  agent is selected.
- **Stored agent**: an agent the user created, kept in the backend database.
  It answers chats with the system prompt it has when each turn starts.
- **User message**: a persisted message with role `user` and non-empty content.
- **Assistant message**: a persisted message with role `assistant`, a model
  name, lifecycle status, and an optional finish reason.
- **Finish reason**: the terminal model reason currently supported by the
  protocol: `stop` or `length`.
- **System prompt**: the instructions an agent sends first in the context of
  every reply. A built-in agent's comes from its backend prompt file
  (`caliginia.txt`, `lysiptera.txt`) and a stored agent's from its record; it
  is not stored with conversations.

## Streaming terms

- **SSE**: Server-Sent Events. The chat endpoint responds as `text/event-stream`
  and emits typed lifecycle events.
- **Start event**: the first event in a chat turn, either
  `start-new-conversation-turn` or `start-existing-conversation-turn`.
- **Delta event**: a streamed assistant text fragment.
- **Done event**: the terminal assistant lifecycle event carrying the finish
  reason.
- **Title event**: the event that publishes a newly assigned or reconciled
  persisted conversation title.

## Handbook terms

- **ADR**: Architecture Decision Record, the reserved format for preserving a
  real decision and its historical context. No ADRs are published yet.
- **RFC**: Request for Comments, the reserved format for tracking a proposal
  before implementation. No RFCs are published yet.
- **docType**: the frontmatter field that tells the docs build whether a page is
  architecture, decision, proposal, runbook, or reference content.
