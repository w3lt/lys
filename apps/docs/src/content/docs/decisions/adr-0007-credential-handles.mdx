## Context

The backend orchestrates provider calls, so the simplest arrangement is for it
to read provider credentials from the operating-system keychain itself. That is
what [ADR-0003](/decisions/adr-0003-backend-reads-keychain/) decided, and it
worked while Lys ran as a single process.

Once the backend became a child process of the Tauri host, the arrangement
required the child to hold keychain-unlock rights for the whole session. A crash
dump, a log line, or a future in-process plugin would then have had access to
long-lived secrets, and the trust boundary between host and backend existed in
the process table but not in what each side could reach.

## Decision

The Tauri host is the only component that reads the keychain. It exchanges a
stored credential for a short-lived, provider-scoped handle and passes the
handle to the backend. The backend attaches the handle to a provider call and
never materialises the underlying secret.

- Handles are scoped to one provider and expire on a fixed lifetime.
- The backend requests a replacement handle rather than caching a secret.
- A handle that fails to resolve produces a typed failure, never a retry with a
  different credential.

## Alternatives considered

Passing the secret itself over the host-backend channel was rejected: it moves
the secret into a second process without reducing what that process can reach,
so the boundary would have been notional.

Keeping ADR-0003 and restricting the backend's keychain access by policy was
rejected because the restriction would have been unenforceable from inside the
backend and invisible in review.

## Consequences

The backend gains a dependency on the host for every provider call, and a
provider call can now fail because a handle expired rather than because the
provider did. That failure is modelled explicitly in
[SSE events](/reference/sse-events/) rather than folded into a generic provider
error.

In exchange, a compromised backend process yields at most one short-lived,
single-provider handle, and the host-backend split became a real trust boundary
rather than a process boundary.
