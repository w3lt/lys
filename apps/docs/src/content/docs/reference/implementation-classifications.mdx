This register preserves earlier source classification labels and records affected
implementation updates. It keeps the connection between implementation and
construction rules in the handbook. It is not a compliance audit, an approval record, or a
claim that each earlier classification is correct. Source declarations remain
authoritative for behavior, ownership, lifecycle, and other callable or rendered
contracts.

The class classifications use [CLASS-003](https://github.com/w3lt/lys/blob/main/docs/code_standards/CLASS.md#class-003--every-class-has-one-primary-category).
The UI classifications use [COMP-006](https://github.com/w3lt/lys/blob/main/docs/code_standards/COMPONENT.md#comp-006--every-component-has-one-primary-category).
Category precedence and permissions remain defined by those canonical rules.
This page records their application without redefining them.

The UI register includes existing labels on variant builders and a context
value; retaining those labels does not establish that those declarations are
Component constructs. Reviewing or correcting classification requires examining
the actual declaration and consumers.

## Maintaining the register

When a declaration changes responsibility, inspect its implementation and
consumers before updating its classification. Keep behavior and lifecycle
documentation beside the declaration; record the selected taxonomy and the
applicable canonical rule here. Use stable source paths and declaration names
rather than source line numbers.

This register covers the migrated labels and the declarations recorded since.
Absence from the table does not establish that a declaration is outside a
standard or has been reviewed.
