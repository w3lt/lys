The repository’s canonical construction rules start in `docs/CODE_STANDARDS.md`.
That file lists the active construct-specific chapters and defines the approval
process for future additions.

## Active standards today

The active chapters are:

- Variable
- Constant
- Function
- Type
- Interface
- Class
- Object
- Component
- Module / file
- Package / dependency
- Hook
- API
- Error
- Event / message
- Async task / stream
- Resource
- Configuration
- Schema / migration
- Test / fixture
- Comment

Every active rule has a stable identifier so reviews can cite the exact rule
without paraphrasing it.

## Ruleset status

All 20 registered chapters are active. No item chapters remain deferred.
Future additions follow the review and explicit approval process in
`docs/CODE_STANDARDS.md`; existing standards remain applicable while a new
chapter is being drafted.

## JSDoc is part of the standard set

For repository-owned JavaScript and TypeScript, `docs/JSDOC.md` is part of the
required reading. It defines which declarations need JSDoc and what those docs
must explain beyond the type signature.

## Exceptions

Exceptions are allowed only under documented technical constraint and require
explicit reviewer approval. The required exception record is defined in
`CONTRIBUTING.md`.

## How to work practically

1. Start with `docs/CODE_STANDARDS.md`.
2. Open the chapter for each construct you are changing.
3. Check `docs/JSDOC.md` if your change touches repository-owned JS or TS.
4. Use rule IDs in review or follow-up notes.

Keep implementation-specific rule mappings and exception evidence in the
handbook's [implementation mappings](/reference/standard-application/). Source
comments explain runtime contracts, and canonical standards define general
requirements; neither carries the mapping between them. See the
[documentation guidelines](/develop/docs/#keep-code-and-construction-rules-independent)
for where each kind of information belongs.
