## Summary

The proposal that became
[ADR-0007](/decisions/adr-0007-credential-handles/): the host issues short-lived
handles instead of sharing keys.

## Motivation

The backend read provider credentials from the operating-system keychain
itself, which placed secret material in the same process as adapter parsing
code and the session store.

## Proposed design

The Tauri host becomes the only keychain reader. It exchanges a stored
credential for a short-lived, provider-scoped handle, and the backend redeems
that handle for an authorised client at call time.

- Handles are scoped to one provider and expire on a fixed lifetime.
- Handles are never persisted, logged, or emitted as events.
- A handle that fails to resolve produces a typed failure, never a silent retry.

## Alternatives

Passing the secret itself across the host-backend channel was considered and
rejected: it moves a secret into a second process without reducing what that
process can reach.

## Risks and trade-offs

Every provider call gains a round trip to the host, and offline development
needs a stub handle issuer.
