This page maps every rule identifier in `docs/code_standards/` to how it is
checked in TypeScript and JavaScript. The rules themselves stay in
`docs/code_standards/`; this page only records which tool decides which part.
Rust and Swift code has no checker: every rule is judged by hand there.

## Classes

Each rule identifier has exactly one class for TypeScript and JavaScript:

- **Exact**: a tool decides the rule, or the part this page names, with no
  false positive under the rule's own definitions. The check is the decision:
  run it and act on its result instead of judging that part by hand.
- **Advisory**: a tool can point at candidates, but a person decides whether
  each one violates the rule. No advisory check is enabled.
- **Review-only**: deciding the rule needs judgment; it is judged by hand.

Only the part named under "Checked part" is decided by the check. Everything
under "Judged by hand", and every rule outside the exact table, is still
judged by hand. When a check misses a violation, the standard still wins:
report the violation and file an issue against the check.

## How the checks run

The checks are rules of the repository's ESLint plugin, `lys`, in
[`tools/code-standards/`](https://github.com/w3lt/lys/tree/main/tools/code-standards),
plus ESLint rules the repository already configures. Each plugin rule is named
after the identifier it checks in lowercase, such as `lys/func-004`, and each
report ends with the identifier and a link to its heading.

- **While writing code**, `pnpm exec eslint <paths>` and editor integrations
  show plugin reports as warnings, for new code and for code that predates a
  rule.
- **For a change**, `node tools/code-standards/check-changed-code.mts` fails
  on every plugin report whose construct overlaps a changed line. This
  follows the compliance scope in `AGENTS.md`: a changed construct must
  comply, while untouched code is not reported. The pre-commit hook runs it
  with `--staged`; CI runs it with `--base` against the pull request's base,
  and `--base origin/main` checks the working tree, untracked files included,
  before review.
- **An exemption** that the rule itself defines, such as a signature a
  framework imposes under `FUNC-004`, is declared on that one declaration with
  `// eslint-disable-next-line lys/<rule> -- <the contract that imposes it>`.
  The directive does not grant an exception the rule does not define.

Declaration files (`*.d.ts`) and declarations inside `declare module`,
`declare global`, or another ambient namespace describe external contracts
and are not checked by the plugin.
