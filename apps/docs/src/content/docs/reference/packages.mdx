The current workspace contains three apps, two shared packages, and one tooling
package. Beside it, outside the pnpm workspace, the repository holds the Rust
crate of the email MCP server Lys ships.

## Workspace map

| Project         | Kind    | Current role                                                                                    |
| --------------- | ------- | ----------------------------------------------------------------------------------------------- |
| `@lys/desktop`  | app     | React UI plus Tauri frontend bindings                                                           |
| `@lys/backend`  | app     | Fastify backend serving health, LLM, chat, conversation history, agent, tool, and MCP endpoints |
| `@lys/docs`     | app     | Astro/Starlight engineering handbook                                                            |
| `@lys/protocol` | package | Shared route constants, request and response schemas, and chat event contracts                  |
| `@lys/share`    | package | Shared conversation, message, and agent schemas                                                 |
| `@lys/scripts`  | tooling | Release-version synchronization from the root `VERSION` file                                    |
| `mcps/email`    | crate   | The email MCP server Lys ships, in Rust, built by Cargo rather than pnpm                        |

## Project notes

### `@lys/desktop`

- Entry UI: `src/App.tsx`
- Native host: `src-tauri`
- Important runtime dependencies: React, Zustand, Tauri API bindings,
  `eventsource-parser`, and `react-markdown` with `@shikijs/rehype`,
  `remark-math`, and `rehype-katex` for assistant replies
- Runtime, Model, and Generation settings share application state. Model controls
  call the backend; generation edits are saved through Tauri and sent with chat requests.
- The past-conversations dialog lists, searches, renames, deletes, and reopens
  stored conversations through the backend history routes.
- The Agents settings pane lists the built-in agents read-only, and lists,
  creates, edits, and deletes stored agents, through the backend agent routes.
- The composer's agent menu selects the agent that answers a new
  conversation.
- The Secrets settings pane saves the Tavily API key of `web_search` through
  Tauri and checks it through the backend.
- The MCP settings pane saves the MCP servers through Tauri, asks the backend
  to apply them, and shows each server's state, tools, and skipped tools,
  with a button that reconnects it; it switches each server on or off, and
  saves the email accounts the built-in email server works with, the
  person's and Lys's own, each once the backend signed in with it, and each
  mailbox's switch.

### `@lys/backend`

- Entry point: `src/index.ts`
- Framework: Fastify
- Important runtime dependencies: `@fastify/sse`, `@lmstudio/sdk`, `openai`,
  `fastify-type-provider-zod`, `@modelcontextprotocol/client`, which connects
  to MCP servers over stdio and Streamable HTTP, and `@mozilla/readability`
  with `linkedom`, which extract a page's main text. `read_page` asks vmo
  through Node's `node:http`, and `web_search` uses Node's `node:https` and
  no search SDK
- `build` (root `pnpm backend:build`) bundles `src/index.ts` with esbuild into
  `dist/backend.mjs` and copies its four prompt files beside it
  (`caliginia.txt`, `lysiptera.txt`, `armitage.txt`, `title-generation.txt`),
  because the bundle reads them from its own directory; `build.sh` installs
  that output as the release backend.
- Starts the email MCP server Lys ships, `mcps/email`, as one built-in stdio
  server for the mailboxes switched on, the person's and Lys's own, tells
  Caliginia and Lysiptera Lys's address through `read_my_state`, and runs its `check` subcommand for the
  email account check; the executable is the file `LYS_EMAIL_SERVER_PATH`
  names, else `$LYS_HOME/runtime/email/email`.

### `@lys/docs`

- Content root: `src/content/docs`
- Framework: Astro with Starlight
- Builds the static handbook published by the checked-in GitHub Pages workflow
- Loads the release sections of the root `CHANGELOG.md` into the `changelog`
  content collection, which the release pages under `/changelog/` render

### `@lys/protocol`

- Re-exports API route modules, constants, and HTTP helpers, including conversation
  list, get, rename, delete, and missing-conversation contracts, and the agent
  list, create, get, update, delete, missing-agent, and taken-code contracts
- Defines the backend loopback host and port constants used by both backend and
  desktop, and the Tavily host that `web_search` sends queries to and the
  approval card names
- Describes the backend tool list with each tool's availability, the
  `web_search` key check, and the backend-tool-unavailable chat problem
- Describes the MCP server list, sync, and reconnect routes, each server's
  state and skipped tools, the server-not-found and server-off problems, and
  the email account check
- Holds the rule, applied by both the backend and the desktop, that refuses a
  `web_search` query holding a character a person cannot reliably see

### `@lys/share`

- Exports Zod schemas and inferred TypeScript types for conversations,
  messages, agents, tools, MCP tool definitions, the MCP server settings with
  their switches, the email account and mail server rules with the rule that
  the person's and Lys's accounts open two mailboxes, JSON values, and
  the API key and email password formats
- Used by both backend persistence code and desktop chat state; the agent
  schemas and limits are used by the backend, `@lys/protocol`, and the desktop
  agent store and editor

### `@lys/scripts`

- Location: `scripts/`
- `version:sync` writes the `major.minor.patch` version in the root `VERSION`
  file into every `package.json` outside dependency, build, and hidden
  directories, plus `apps/desktop/src-tauri/tauri.conf.json` and
  `apps/desktop/src-tauri/Cargo.toml`. It rewrites only manifests whose version
  differs; a rewritten `Cargo.toml` is normalized and loses its comments.
- `version:check` lists each manifest whose version is missing or differs from
  `VERSION` and exits with status 1 when any does.
- Run either with `pnpm --filter @lys/scripts run version:sync` or
  `pnpm --filter @lys/scripts run version:check`.

### `mcps/email`

- Location: `mcps/email`, a Rust crate with its own `Cargo.toml` and
  `Cargo.lock`, outside the pnpm workspace
- The email MCP server Lys ships: it reads, searches, sends, and files the
  person's mail over one IMAP and SMTP account through ten MCP tools served
  over stdio, and `email check` signs in to both servers and prints a report
  for the backend's account check; see
  [the email server](/architecture/backend/#the-email-server) and
  [its tools](/reference/api/#the-email-servers-tools)
- Important dependencies: `rmcp` (the MCP server), `async-imap` and `lettre`
  (IMAP and SMTP), `mail-parser`, and `tokio` with `tokio-rustls` and
  `rustls-platform-verifier`, which verifies certificates against the
  operating system's store
- Built for development with
  `cargo build --manifest-path mcps/email/Cargo.toml --target-dir mcps/email/target`;
  `build.sh` builds it in release and installs it as
  `$LYS_HOME/runtime/email/email`.
  Its checks are the Cargo commands in
  [Testing and validation](/develop/testing/)
